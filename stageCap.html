Stage chez Capgemini — Projet GoGemini

Présentation du stage

Dans le cadre de ma troisième année de BUT Informatique, j'ai réalisé un stage chez Capgemini, entre les sites de Montbonnot et du Bourget-du-Lac, du 20 avril 2026 au 12 juin 2026.

J'ai intégré le projet GoGemini, une application web destinée à gérer et visualiser des organigrammes d'entreprise de manière interactive.

Ma mission principale a été de concevoir le backend complet de l'application et de mettre en place la logique métier nécessaire au fonctionnement des différentes fonctionnalités.

Contexte du projet

Les organigrammes de l'entreprise étaient auparavant principalement gérés à l'aide de fichiers Excel. Cette organisation rendait les mises à jour plus longues, compliquait le partage des informations et pouvait entraîner des erreurs.

Le projet GoGemini avait pour objectif de proposer une application web centralisée permettant de gérer ces données plus facilement et de représenter les relations hiérarchiques de façon claire et interactive.

Objectifs du projet

  • Centraliser la gestion des organigrammes d'entreprise.
  • Remplacer les fichiers Excel par une application web plus fiable.
  • Créer un backend capable de gérer les données et les règles métier.
  • Mettre en place une base de données persistante.
  • Permettre l'import et l'export des données au format Excel.
  • Visualiser les structures hiérarchiques de manière interactive.
  • Améliorer l'ergonomie globale de l'application.

Technologies utilisées

  • Node.js : environnement d'exécution du backend.
  • Fastify : création de l'API REST et gestion des routes serveur.
  • MongoDB : stockage persistant des organigrammes et des données associées.
  • Angular : framework utilisé pour le frontend déjà existant.
  • TypeScript : langage utilisé côté frontend et backend.
  • D3.js : visualisation interactive des organigrammes.
  • Tailwind CSS : participation à la refonte graphique de l'interface.
  • Insomnia : tests et validation des routes API.
  • GitHub et Trello : gestion du code source et suivi des tâches.

Contributions réalisées

  • Analyse du projet existant : prise en main du frontend Angular déjà développé afin d'identifier les données nécessaires et les besoins côté serveur.
  • Conception du backend : mise en place de l'architecture serveur avec Node.js et Fastify.
  • Création de la logique métier : développement des règles permettant de gérer les organigrammes, leurs données, leurs relations hiérarchiques et les actions utilisateurs.
  • Création de l'API REST : développement des routes nécessaires pour récupérer, créer, modifier et supprimer les données de l'application.
  • Gestion des requêtes HTTP : utilisation des méthodes GET, POST, PUT et DELETE pour permettre la communication entre le frontend et le backend.
  • Connexion à MongoDB : intégration de la base de données afin de garantir la persistance des organigrammes et des informations associées.
  • Gestion des erreurs : ajout de contrôles et de réponses adaptées afin de sécuriser les échanges entre le frontend et le serveur.
  • Import et export Excel : participation à la logique permettant d'importer des données depuis des fichiers Excel et de les exporter.
  • Tests du backend : vérification des routes API avec Insomnia, correction des bugs et validation du bon fonctionnement des échanges avec la base de données.
  • Refonte graphique : participation à l'amélioration visuelle de l'interface existante afin de la rendre plus claire et plus agréable à utiliser.

Architecture de l'application

L'application repose sur une architecture client-serveur composée de trois parties principales :

  • Frontend : une interface Angular permettant aux utilisateurs de consulter, créer et modifier les organigrammes.
  • Backend : une API REST développée avec Node.js et Fastify, chargée de gérer la logique métier, les requêtes et les échanges de données.
  • Base de données : MongoDB, utilisée pour stocker durablement les organigrammes et leurs informations associées.

Le frontend communique avec le backend grâce à des requêtes HTTP. L'API REST permet notamment de créer, consulter, modifier et supprimer les données selon les besoins de l'application.

Fonctionnalités prises en charge côté backend

  • Création, récupération, modification et suppression des organigrammes.
  • Gestion de la persistance des données dans MongoDB.
  • Gestion des relations hiérarchiques entre les éléments d'un organigramme.
  • Création des routes API nécessaires au fonctionnement de l'application.
  • Validation des données reçues par le serveur.
  • Gestion des erreurs et renvoi de réponses HTTP adaptées.
  • Communication entre le frontend Angular et la base de données.
  • Traitement des données liées à l'import et à l'export de fichiers Excel.
  • Tests des différentes routes avec Insomnia.

Compétences développées

  • Conception d'une architecture backend.
  • Développement d'une API REST avec Fastify.
  • Création de routes HTTP et gestion des méthodes GET, POST, PUT et DELETE.
  • Développement de logique métier côté serveur.
  • Connexion et gestion de données avec MongoDB.
  • Gestion des erreurs et validation des données.
  • Tests d'API avec Insomnia.
  • Compréhension d'une architecture frontend / backend.
  • Utilisation de GitHub et Trello dans un contexte professionnel.
  • Participation à une refonte graphique d'interface.

Bilan

Ce stage m'a permis de participer à un projet concret répondant à un besoin réel en entreprise. J'ai pu concevoir le backend de l'application, créer son API REST, développer sa logique métier et assurer la persistance des données avec MongoDB.

Cette expérience m'a permis de renforcer mes compétences en développement backend, en architecture client-serveur, en gestion de base de données et en tests d'API. Elle m'a également permis de découvrir l'organisation d'un projet informatique dans un environnement professionnel.
